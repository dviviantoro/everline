## Apa Ini?

A map-based POC tracking PLN's 20kV transformers and power lines in Central Java, with historical field-survey data — electrical readings on transformers, partial-discharge and temperature readings along lines — so degradation is visible before it causes an outage. Dummy data only; not connected to any real PLN system.

**This is the frontend only.** The database, API, and all write/read logic live in `../backend/` — a separate, self-hosted service (see `../backend/README.md`). This app has no server-side database access at all; every data operation goes through `lib/api.ts` to that external API.

## Quick Start

### Prerequisites

- Node.js 20+ and npm
- A running backend to point at — either the deployed VPS instance (see `../backend/README.md`), or `../backend`'s Docker Compose stack running locally

### Setup

```bash
# From the repo root
cd apps

# Install dependencies
npm install

# Setup environment
cp .env.example .env.local
# Edit .env.local:
#   NEXT_PUBLIC_API_BASE_URL — the backend's URL (e.g. https://api.yourdomain.com,
#     or https://localhost if running ../backend's Docker Compose stack locally)
#   NEXT_PUBLIC_API_KEY — must match the API_KEY set in ../backend/.env

# Run the dev server
npm run dev
```

If the backend is running locally via Docker Compose with a self-signed cert (`API_DOMAIN=localhost` in `backend/.env`), your browser will show a certificate warning the first time it calls the API — that's expected for local dev (see `../backend/README.md`'s local development section).

### Access

| Service | URL |
|---------|-----|
| Landing page | `http://localhost:3000` |
| Sign in | `http://localhost:3000/login` |
| Map dashboard | `http://localhost:3000/dashboard` |
| Asset registry | `http://localhost:3000/registry` |
| Reports | `http://localhost:3000/reports` |
| API (external, self-hosted) | `NEXT_PUBLIC_API_BASE_URL` — see `../backend/README.md` |

## API

All routes now live in the separate backend service — see `../backend/README.md` for the full route list, and `https://<your-backend-domain>/docs` for interactive Swagger docs once it's running. Every request needs an `X-API-Key` header (`lib/api.ts` attaches it automatically using `NEXT_PUBLIC_API_KEY`).

**The one rule that matters most, unchanged:** `surveys`, `transformer_readings`, and `pd_readings` are insert-only. Never write an UPDATE or DELETE against them.
