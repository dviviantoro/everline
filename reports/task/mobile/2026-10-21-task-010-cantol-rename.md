4.4 Kept on purpose

| Where | Text | Why it stays |
|-------|------|--------------|
| mobile/rust/cantol-proto/tests/vectors.rs, src/msg.rs (test) | `b"RP-00A1\0"` device id | The same 8 bytes are inside the committed `mobile/rust/vectors/decode/clean_10.bin`. `vectors.rs` rebuilds that stream and compares it; changing the id changes the payload CRC in `clean_10.json` and therefore the digest. A comment in `vectors.rs` records this. |
| mobile/rust/cantol-mock/src/config.rs, src/main.rs (usage), tests/e2e.rs | `RP-MOCK` default device id | It is what the mock advertises on the wire, not prose. Renaming it changes the mock's observable output, and the field is 8 bytes (a name such as `CANTOL-MOCK` does not fit). The id format belongs to ADR-005. |
| mobile/rust/cantol-mock/src/main.rs (test) | `RP-01` | A command-line test value for `--device-id`, paired with the line above. |

Decision for the user: pick the device-id format (and a replacement for these three strings, for example a `CT-` prefix) when ADR-005 is written. The vectors would then be regenerated deliberately with `UPDATE_VECTORS=1`, and the new digest recorded.
